# Address Matching GPB — компонентный прототип v2

Сопоставление «грязного» адреса с записью эталонного справочника.
Продолжение исходного TF-IDF + RapidFuzz baseline: теперь учитываются компоненты
адреса и возможность отказа от автоматического совпадения.

## Быстрый запуск

Python **3.10–3.12**; проверено на Python 3.12. Для приложения не нужны GPU,
OSMnx, ключи API, внешние модели или доступ к интернету после установки зависимостей.

```bash
python -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

В браузере откройте адрес, который выведет Streamlit, обычно http://localhost:8501.
Встроенный справочник содержит **17 синтетических демонстрационных записей**,
а не проверенные реальные адреса. Прежний OSM-корпус из 6 448 адресов в исходном
архиве отсутствовал. Загрузите свой CSV через боковую панель.

Примеры для интерфейса:

- `Красноярск, ул. Ленина 25` → запись с регионом и районом из справочника.
- `г.Красноярск,ул.Ленина,д.25` → восстановление отсутствующих пробелов.
- `г. Горький, ул. Ленина, д. 10` → Нижний Новгород по словарю алиасов города.
- `Курская обл., Железногорск, ул. Ленина 25` → Железногорск Курской области.
- `Железногорск, ул. Ленина 25` → требуется уточнение региона.
- `Москва, ул. Ленина 10к2` → дом 10, корпус 2.
- `Москва, ул. Ленина 10` → требуется уточнение корпуса/строения.

Один адрес и CSV с колонкой `query` поддерживаются в интерфейсе.
В результате показывается один принятый адрес; диагностические кандидаты спрятаны
в раскрывающийся блок. Score — **не вероятность правильного совпадения**.

## Загрузка реальных адресов из OSM

Если `reference_osm.csv` отсутствует, теперь его создаёт отдельный загрузчик.
Из корня проекта:

```bash
python -m pip install -r requirements-osm.txt
python scripts/download_reference_osm.py
```

Пути по умолчанию определяются относительно файла скрипта, а не `/content` или
текущей папки терминала. Можно запускать по абсолютному пути из любой директории.
`reference_osm.csv` и `reference_osm.meta.json` появятся в корне проекта.
Загрузка обращается к внешним сервисам, поэтому нужен интернет; она может занять
несколько минут. Это новый снимок OSM, а не восстановление прежних 6 448 записей.

Существующий непустой CSV используется повторно. Для новой выгрузки:

```bash
python scripts/download_reference_osm.py --refresh
```

Параметры:

- `--places data/osm_places.json`: JSON со списком районов и городов. Включены
  Северное Тушино, Южное Тушино и Центральный район Санкт-Петербурга.
- `--output /путь/к/reference_osm.csv`: другое место сохранения; родительские папки
  создаются автоматически. Относительный пользовательский путь считается от cwd.
- `--timeout 180`: таймаут одного HTTP-запроса, не всего процесса. OSMnx может ждать
  разрешения сервера на запрос, поэтому суммарное время бывает больше.
- `--allow-partial`: явно разрешить неполный результат, если часть районов недоступна.

Если район не загрузился или не содержит подходящих адресов, обычный запуск
завершится с кодом 1. Основной CSV и его метаданные не меняются. Доступные адреса
сохраняются в `reference_osm.partial.csv`, причины — в `reference_osm.attempt.json`.
Повторите команду позже. Не считайте частичную выгрузку полным справочником.
При смене списка районов нужен новый `--output` или `--refresh`.
Для старого CSV без метаданных география и полнота не подтверждаются.

Сборщик сохраняет строки с улицей и домом, удаляет дубли по нормализованным
компонентам, сохраняет ссылки на OSM-объекты в `osm_ids` и районы загрузки в
`source_places`. `id` — SHA-256 от компонентов адреса, стабилен при перестановке
строк, но меняется при изменении компонентов; это не официальный ID ГАР/ФИАС.
Город из `addr:city` имеет приоритет над городом из конфигурации, если заполнен.
Регион — `addr:region`, затем значение `region` из конфигурации. Поле `source_places`
не подставляется в адресный `district`: название поисковой области не является
достоверным компонентом каждого объекта. Сложные адресные номера требуют
дополнительной проверки парсера; сборщик не делает OSM официальным справочником.

После загрузки:

```python
from src.io import ROOT, read_reference, read_aliases
from src.hybrid import HybridAddressMatcher
reference = read_reference(ROOT / 'reference_osm.csv')
matcher = HybridAddressMatcher().fit(reference, read_aliases())
result = matcher.match_one(reference.iloc[0]['address'])
print(result.status, result.best, result.reasons)
```

## Архитектура

1. **Нормализация и разбор**: регион, город, район, тип улицы, улица, дом,
   корпус, строение, квартира. Справочник формирует словарь названий; алиасы
   загружаются отдельно. Сохраняются буквы и `/` в доме, суффиксы городов.
2. **Поиск кандидатов и решение по паре**: символьный TF-IDF (2–4 граммы)
   плюс объединение с точным компонентным блоком. Для каждого кандидата считается
   компонентное сходство и проверяются противоречия. Выбирается один результат
   или отказ от автоматического принятия.

По умолчанию:

```text
component_score = Σ(weight[field] × similarity[field]) / Σ(weight[present query fields])
score = 0.85 × component_score + 0.15 × tfidf_cosine
```

Веса: регион 2, город 3, район 0.3, тип улицы 0.5, улица 3, дом 3,
корпус 2, строение 2, квартира 1. Строковое сходство — RapidFuzz ratio на значении
компонента без пробелов. Это **эвристики**, не обученные или калиброванные параметры.

Явные несовпадения региона, типа улицы, дома/корпуса/строения/квартиры запрещают
автоматический матч. Для города допускается небольшая буквенная опечатка
(similarity ≥ 0.88), но числовые части должны совпадать. Сходство улицы ниже 0.68
считается конфликтом. Если компонент указан в запросе, но отсутствует в эталоне,
он считается непроверенным. Район — мягкий дополнительный признак.

Для принятия нужны город, улица и дом, отсутствие предупреждений/конфликтов,
score ≥ 0.84 и отрыв от следующего допустимого кандидата ≥ 0.06. Несколько
полностью совместимых эталонных записей означают неоднозначность независимо от
текстового score. При единственном допустимом кандидате margin равен его score.
Решения:

- `accepted`: `best` и `best_id` заполнены.
- `review`: данных недостаточно для однозначного автоматического принятия.
- `no_match`: надёжное совпадение не установлено. **Не доказательство отсутствия
  адреса в мире или даже в справочнике** — возможна ошибка парсера.

`candidate` / `candidate_id` содержат диагностический top-1 даже при отказе;
использовать их как исправленный адрес без проверки `status` нельзя.

Причины: `conflict_*` — несовпадение, `unverified_*` — нет значения в эталоне,
`ambiguous_*` — неоднозначность, `incomplete_identity` — недостаточно компонентов,
`low_score` — низкий score, `small_margin` — малый отрыв.

## Формат справочника

Минимально: колонка `address`, либо `united_addr` для совместимости с OSM-кешем.
Рекомендуется структурированный CSV, как `data/reference_demo.csv`:

```csv
id,address,region,city,street_type,street,house,building,structure
001,"Москва, ул. Ленина, д. 10, корп. 2",,Москва,улица,Ленина,10,2,
```

Читайте все колонки как строки: ID, `10А`, `10/2` нельзя приводить к числам.
ID должны быть уникальными и непустыми. При отсутствии ID используются номера
строк; для рабочих данных необходимы устойчивые идентификаторы, например ID из
вашего адресного справочника. Дубли адресных сущностей с разными ID нужно заранее
объединять: система консервативно трактует их как неоднозначность.

Дополнительно поддерживаются `addr:city`, `addr:street`, `addr:housenumber`.
Для полного покрытия регионов и одноимённых городов предпочтителен справочник
с явными компонентами. Исходная выгрузка OSM не превращается автоматически
в полный официальный адресный справочник.

```python
from src.io import read_reference, read_aliases
from src.hybrid import HybridAddressMatcher

matcher = HybridAddressMatcher().fit(
    read_reference('data/reference_demo.csv'), read_aliases()
)
result = matcher.match_one('Красноярск, ул. Ленина 25')
print(result.status, result.best_id, result.best, result.reasons)
```

## Аугментации и разметка

```bash
python scripts/generate_queries.py --reference data/reference_demo.csv --output data/generated_queries.csv
```

Есть чистые адреса, перестановки компонентов, отсутствие пробелов, типовые
сокращения, сокращённые названия улиц, неполные адреса и перестановка соседних букв.
Seed фиксируется. Старые keyboard/random-insert эксперименты сохранены в `code/`.
Исторические названия и близкие города проверяются отдельным ручным набором.

Недопустима позитивная разметка случайной перестановки всех слов: `Нижний Новгород`,
`8 Марта`, дом/корпус — смысловые группы. Обмен значений дома и корпуса получает
ID нового адреса, если он есть, иначе пустой `true_id`. При удалении региона и
сокращении улицы разметка проверяет уникальность **по исходным структурированным
компонентам**, без вызова тестируемого парсера или ранжирования.

`source_id` сохраняет исходную сущность. Разбиение 60/20/20 — по source_id, не по
строкам аугментаций. При изменении корпуса список групп и split может измениться,
поэтому сохраняйте готовый CSV. Эталон остаётся целиком в поисковом индексе: это
закрытая задача retrieval, а не обучение на test-ответах. Train сейчас резервный:
обучаемого ранкера нет. Для строгого обобщения дополнительно отделяйте регионы,
семейства неоднозначных адресов и типы шумов; связанных сущностей одного source_id
недостаточно для такого теста.

## Метрики и воспроизводимость

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python scripts/evaluate.py
python scripts/evaluate.py --reference reference_osm.csv --queries queries.csv --output reports/real
```

Формат `queries.csv`: `query,true_id,category`, опционально `source_id,split`.
Пустой `true_id` означает **нет однозначно допустимого автоматического ответа**:
как неизвестный адрес, так и запрос, требующий уточнения. Это нужно различать в
`category`. Для нескольких допустимых ID потребуется расширить схему разметки;
текущая реализация их консервативно относит к review.

`evaluate.py` сохраняет `predictions.csv`, `metrics.csv`, `config.json`:

- **HitRate@1 / Accuracy@1**: доля верных top-1 среди запросов с единственным true_id,
  до применения порога. При единственной правильной сущности это одна метрика.
- **Pair precision/recall/F1/accuracy**: классификация пары «запрос, top-1».
  Истинная метка 1, если ID top-1 равен непустому true_id; предсказание 1 при accepted.
  Это бинарная проверка выбранной пары, не всех возможных пар справочника.
- **Resolution recall**: число правильных принятых совпадений / число запросов с
  true_id. Учитывает потерянные ответы на retrieval. Неверное принятие — ложная
  связь и одновременно пропущенная правильная связь. Resolution F1 объединяет
  этот recall с precision принятых связей.
- **Coverage**: доля автоматических принятий, включая ошибки.
- **Decision accuracy**: правильный принятый ID для однозначных запросов либо
  корректный отказ для запросов без однозначного ответа.

Именно поэтому pair recall нельзя подменять полным recall системы: если правильный
адрес не попал в top-1, отрицательная пара может быть классифицирована правильно,
но задача сопоставления остаётся нерешённой. Метрики выводятся также по категориям.
При нулевом знаменателе PR/F1 возвращаются как 0; HitRate без matchable-запросов — null.

Подбор параметров **только на validation**:

```bash
python scripts/calibrate.py --reference data/reference_demo.csv --queries data/generated_queries.csv --min-precision 0.98
# Возьмите threshold и margin из reports/calibration/selected.json:
python scripts/evaluate.py --reference data/reference_demo.csv --queries data/generated_queries.csv --split test --threshold 0.84 --margin 0.06 --output reports/test
```

В последней команде показаны исходные пороги; замените их выбранными значениями.
Если допустимой конфигурации нет, скрипт честно возвращает `no_feasible_configuration`.
Точечный precision на нескольких примерах не подтверждает 98% на реальных данных.
На рабочем корпусе нужны существенно больше реальных negative/ambiguous запросов,
отложенный test и интервальные оценки с учётом группировки аугментаций.

## Эксперименты этой версии

Результаты находятся в `reports/EXPERIMENTS.md`. Ручные кейсы и синтетический набор
использовались для разработки — **это regression/development checks, не независимый
бенчмарк**. Прежние 0.96 на 100 адресах из OSM не пересчитывались и напрямую с
новыми результатами не сравниваются. Пороги baseline (.85) и hybrid (.84/.06)
эвристические; для честного продуктового сравнения подбирайте оба на одинаковом
validation при одинаковом требовании precision/coverage.

## Опциональный реранкер

`HybridAddressMatcher(reranker=callable, rerank_enabled=True)` принимает функцию
`(query, list[str]) -> list[float]` со score в [0, 1]. Он вызывается только при
малом отрыве двух допустимых кандидатов, отсутствии конфликтов, неоднозначности
и неполной идентичности. Смешивание: 80% hybrid + 20% reranker. Структурные
запреты реранкер не отменяет; пороги принятия применяются снова.

Готовая нейронная модель не подключена; маршрутизация — **точка расширения**.
Перед включением: зафиксировать маршрут, сравнить ON/OFF на отложенной выборке,
проверить ошибки по категориям и задержку. Нет обещания, что неспецифичный reranker
поможет. Дообучение эмбеддера/реранкера оставлено за рамками текущего прототипа.

## Ограничения

- Парсер на правилах и словаре эталона, не универсальный промышленный парсер РФ.
  Неизвестные обозначения, сложная административная иерархия, литеры, владения,
  участки, километры трасс и сочетания сильных шумов требуют расширения и тестов.
- Восстановление полностью склеенных строк зависит от известных названий и
  распознаваемых маркеров. Разбор неизвестных склеенных топонимов не гарантируется.
- Алиасы — небольшой редактируемый JSON, без временных интервалов и внешнего
  справочника переименований. Красноярск-45 в демо проверяет различимость строк,
  не является автоматически привязанным современным историческим алиасом.
- Неуказанные корпус/строение не автоматически равны их отсутствию; если подходит
  несколько записей, требуется уточнение. Квартиры сверх детализации справочника
  блокируют автоматическое принятие.
- Словарь и индекс в памяти; TF-IDF оценивает весь корпус, а точные блоки могут
  расширять пул. Сотни тысяч/миллионы записей и нагрузка не тестировались.
- Пороги, веса и качество извлечения компонентов требуют калибровки на рабочем
  корпусе. Совпадение 100% на маленьком созданном наборе не доказывает качество
  на реальных адресах.

## Структура и совместимость

`src/baseline.py`, `src/baseline_normalize.py` — исходный baseline без изменения
алгоритма; `src/matcher.py` сохраняет старый импорт `AddressMatcher`.
`code/1_ideal_address.py` остаётся прежним OSM/Colab-экспериментом, отдельно от UI;
его зависимости — `code/requirements.txt`, дополнительно IPython для вывода.
Исходный отчёт сохранён как `docs/README.md` и описывает **первую версию**.

Новые точки входа: `app.py`, `scripts/generate_queries.py`, `scripts/evaluate.py`,
`scripts/calibrate.py`. Новые модули: `parser.py`, `hybrid.py`, `augmentation.py`,
`evaluation.py`, `io.py`. `tests/` содержит проверки требований и защит от регрессий.
